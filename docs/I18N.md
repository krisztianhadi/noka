# Adding a language

noka ships five languages today: English, Spanish, French, Chinese (Simplified) and Russian.
Adding a sixth is a small, self-contained pull request — no application code changes, no build
configuration, and the compiler tells you when you are done.

## What to change

Three files, in this order.

**1. `src/i18n/locales/<code>.ts`** — copy `en.ts` and translate the values. Keep every key
exactly as it is; only the right-hand side changes.

```ts
import type { MessageKey } from '../keys';

/** German. Missing keys are a compile error — see `src/i18n/keys.ts`. */
const de: Record<MessageKey, string> = {
  'pin.title': 'Notfallkontakte',
  // …every other key, in the same order as English
};

export default de;
```

**2. `src/i18n/locales/index.ts`** — add the import and one entry.

```ts
import de from './de';
export const MESSAGES: Record<CardLanguage, Record<MessageKey, string>> = { en, es, fr, zh, ru, de };
```

**3. `src/i18n/languages.ts`** — add the code to `CARD_LANGUAGES` and its entry in
`LANGUAGE_INFO`. The `endonym` is the language's own name for itself (`Deutsch`), because a
speaker should recognise it without reading the rest of the page. Set `dir` from the language's
script — every language shipped today is `ltr`, and both layouts already write the attribute.

```ts
export const CARD_LANGUAGES = ['en', 'es', 'fr', 'zh', 'ru', 'de'] as const;

export const LANGUAGE_INFO: Record<CardLanguage, LanguageInfo> = {
  // …
  de: { dir: 'ltr', endonym: 'Deutsch', englishName: 'German', htmlLang: 'de' },
};
```

**4. `src/i18n/card-copy.ts`** — the printed artwork's own strings, typed
`Record<CardLanguage, CardPhrase>`. It is a separate file because the card is typeset into a fixed
638 × 1011 px artwork: a long translation breaks the layout, so it is checked by eye as well as by
the compiler. Adding a language without an entry here does not compile.

That is the whole change. `CARD_LANGUAGES` drives the printed card's language set, the responder
pages and the owner plane at once, so a card cannot be printed in a language its own page cannot
speak.

**Before you translate into a right-to-left language** (Arabic, Hebrew, Farsi), read this first: the
`dir` attribute is wired, but nobody has looked at the layouts mirrored. The responder page's
`.actions` grid, the card artwork and the dashboard's kebab menus are all untested in RTL. Adding
Arabic is a metadata change plus a visual pass, not just a file.

**Pluralisation is not solved yet.** English, Spanish, French and Russian all need more than the
hand-written "one person / N people" pair the dashboard does today; Chinese needs none. If your
language has more plural forms than that, open an issue and the fix is `Intl.PluralRules` for the
keys that take a count — worth doing properly rather than guessed per language.

## Rules the build enforces

- **Every key, or it does not compile.** Each locale file is typed `Record<MessageKey, string>`,
  where `MessageKey` is derived from `en.ts`. A missing key is a TypeScript error naming the key.
- **No invented keys.** An extra key fails the same type check, and the test suite rejects it too.
- **Placeholders must survive.** `{name}` and `{count}` are substituted at render; a test compares
  the placeholder set of every language against English, because a lost `{name}` is a sentence that
  renders with a hole in it.
- **No empty strings, no `TODO` markers.** The suite fails on both.

## Checking your work

```bash
pnpm i18n:report   # coverage per language, and exactly which keys are missing
pnpm typecheck     # the compiler's version of the same answer
pnpm test          # parity, placeholders, empty values
```

`pnpm i18n:report` reads the files with a regex rather than importing them, so it works on a
half-finished translation — paste its output into your pull request and a reviewer can see the
state at a glance.

## Translation guidance

- **Translate, do not transliterate.** "Nobody yet" should read like something a person would say
  in your language, not like English with your words in it.
- **Keep the register consistent** with the existing file: Spanish uses informal *tú*, French
  *vous*, Russian formal *вы*.
- **Brand names stay as they are:** noka, WhatsApp, Signal, Telegram, Viber, QR, PIN, JSON, ADR-004.
- **This is an emergency product.** The reader may be frightened and in a hurry. Short, plain and
  unambiguous beats elegant. Never soften a destructive-action confirmation: "permanently", "cannot
  be undone" and "the printed card stops working immediately" must stay unmistakable.
- **Em dashes stay em dashes** (—), and proper typography for your language is welcome.
- **Nothing the owner typed is ever translated:** names, notes, phone numbers and spoken languages
  are shown exactly as entered.

## Where the strings come from

One catalogue serves both planes: the responder pages (`/c/*`, opened by whoever finds the card)
and the owner plane (dashboard, settings, auth, landing). That means one file per language covers
everything a person can read, and a translator does not need to know which half of the app a string
belongs to.

The printed card's own copy is separate — `src/i18n/card-copy.ts` — because it is typeset into a
fixed 638 × 1011 px artwork, so a long translation can break the layout. If you are adding a
language that needs significantly longer words, check the card render (`/dashboard/card/card.jpg`)
before you finish.

The legal pages (`/privacy`, `/terms`, `/imprint`) are English only, deliberately: they are
jurisdiction-bound prose, and a machine-adjacent translation of a privacy policy is worse than a
clearly-marked English one. If you are a lawyer and want to contribute a reviewed translation, open
an issue first.
