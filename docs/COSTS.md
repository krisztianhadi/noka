# What building this costs

Two lanes, and only one of them has a price.

| Lane | What it is for | Cost |
|---|---|---|
| DeepSeek webchat (free tier) | Brainstorming, the specification, the plan, thinking out loud | **€0** — it is the free chat, not the API |
| DeepSeek API via this harness | Writing the code, the tests, the docs, running the build | **Usage-based**, billed by the provider |
| Infrastructure | Postgres, hosting | **Not yet spent** — nothing is deployed |

The point of this file is to keep an honest record while the project is small.
Most side projects have no idea what they cost, and "it felt cheap" is not a
number.

`Total` is the sum of input, output and cached-prompt tokens. Cache reads
dominate because the harness resends the whole conversation with each request
and the provider serves most of it from cache — which is also why the input
figure alone would be misleading.

## Why there is no money column

**Tokens are not money here.** The provider's rates change by time of day
(off-peak pricing), and the mix of cache reads, input and output is priced
differently in each window. Multiplying a token total by a list price would
produce a number that looks precise and is wrong.

To turn this into a price, take the totals above and the provider's billing page
for the same date window — which is the only source that knows what was actually
charged. Two lanes, one invoice: the chat is free and the API is not.

## Refreshing this file

```sh
node scripts/usage-report.mjs           # print the table
node scripts/usage-report.mjs --write   # rewrite the block above
```

The script reads the harness's own logs: nothing to maintain, nothing to
remember to log by hand. It counts this workspace only, and it says so when a
session has no usage records.

## What this file is not

- Not a budget. There is no cap in place; this records, it does not brake.
- Not a forecast. A phase that goes smoothly costs less than one that fights the
  framework, and so far the second kind has been the norm — three of the six
  working blocks in the devlog were spent on bugs the tests caught.
- Not the whole picture of effort. The free lane carries the thinking, and the
  thinking is the part that decides whether the code was worth writing.
